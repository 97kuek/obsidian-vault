## 離散数学 形式言語と有限オートマトン

> 形式言語、正規文法、有限オートマトン、文脈自由文法、構文解析、依存構造解析を整理する授業ノートである。

## 全体像

| 領域 | 主な内容 | 重要ポイント |
|---|---|---|
| 形式言語 | アルファベット、記号列、言語、文法 | 有限の規則で無限の言語を表せる |
| 正規言語 | 正規文法、有限オートマトン、NFA/DFA | 正規文法と有限オートマトンは等価である |
| 非正規性 | 反復補題、`aⁿbⁿ` の証明 | 有限状態では無限に大きい個数対応を覚えられない |
| 文脈自由言語 | CFG、曖昧性、標準形 | CFG は入れ子構造を表せる |
| 構文解析 | CKY、依存構造解析 | 動的計画法やグラフアルゴリズムで構文を求める |

## 1. 形式言語の基礎

### 1.1 構文 (syntax) とは

- 文は表面上「一次元の語の並び」だが、内部には**構造**がある
- この構造を **構文 (syntax)** とよび、一般に**木**で表現する
- 表現方法は大きく2種類である

| 表現 | 考え方 |
|---|---|
| **句構造 (phrase structure)** | 語をまとめて句(NP, VP, …)を作り、階層的に組み上げる |
| **依存構造 (dependency structure)** | 語と語の間に「主辞(head) → 従属語(dependent)」の関係を張る |

#### 句構造の例(英語)

```text
S → NP VP        VP → V
NP → N           VP → V NP
NP → DET N       VP → VP PP
NP → NP PP       PP → PREP NP
```

- "I saw a girl with a telescope" は `I/N saw/V a/DET girl/N with/PREP a/DET telescope/N`
- これを上の規則で組み上げると S に到達する

#### 句構造の例(日本語)

```text
Sentence → PP PP Verb
PP → Noun Postposition        ※PP = 後置詞句
```

- 「私 は 本 を 読んだ」→ (私は)(本を)(読んだ)
- 日本語は助詞(後置詞)が名詞にくっつく点が英語と大きく違う

### 1.2 言語の形式的定義

- **アルファベット Σ**: 記号の**有限**集合
    - 例: Σ = {0, 1}、音素の集合、英字の集合、英単語の集合
- **記号列 (string)**: Σ の元を有限個並べたもの
    - Σ⁰ = {ε} (ε は空列)
    - Σ¹ = {0, 1}
    - Σ² = {00, 01, 10, 11}
    - Σⁿ = 長さ n の記号列全体
- **Σ*** = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ … = {ε, 0, 1, 00, 01, 10, 11, 000, …}
    - Σ 上の**有限長**記号列すべての集合(**可算無限**集合)
    - 注意: 各記号列は有限長だが、集合としては無限個ある
- **言語 L**: Σ* の**部分集合** (L ⊆ Σ*)
- **文 s**: 言語の元 (s ∈ L)
- **文法 G**: 言語 L を**生成する**有限の装置

> 言語は無限集合になりうるが、文法は**有限の規則の集合**である。
> 有限の規則で無限の言語を書き表せる、というのがこの理論の核心。

### 1.3 句構造文法 (Phrase Structure Grammar)

- **G = ⟨N, T, P, S⟩** の4つ組で定義

| 記号 | 意味 |
|---|---|
| **N** | 非終端記号 (nonterminal) の有限集合。S, NP, VP など、書き換え途中に現れる記号 |
| **T** | 終端記号 (terminal) の有限集合。実際に文に現れる記号(単語・文字) |
| **P** | 生成規則 (production rule / 書換え規則) の有限集合 |
| **S** | 初期記号 (start symbol)。`S ∈ N` |

- 生成規則の形は `α → β` である
    - `α ∈ (N ∪ T)⁺`
    - `β ∈ (N ∪ T)*`
    - `α` は空でない記号列、`β` は空列でもよい記号列である

#### 導出の例

```text
S → aA
A → aA
A → a
```

- 導出: `S ⇒ aA ⇒ aaA ⇒ aaa`
- この導出過程を木で描いたものが **導出木 (derivation tree)** / 構文木
- この文法が生成する言語は L = {aⁿ | n ≥ 2}

## 2. 正規言語と有限オートマトン

### 2.1 正規文法 (Regular Grammar)

- 生成規則が次の形に**限定**されたもの(**右線形**)
    - **A → aB** (A, B ∈ N, a ∈ T)
    - **A → a**
- つまり「終端記号1つ + 非終端記号1つ」または「終端記号1つ」だけ

#### 例

```text
S → aA    S → bB
A → aA    A → a
B → bB    B → b
```

- S から a で始まる枝に入ると a しか出せず、b で始まる枝に入ると b しか出せない
- 生成される言語は **L = {aⁿ | n ≥ 2} ∪ {bⁿ | n ≥ 2}**
    - 例: S ⇒ aA ⇒ aa、S ⇒ aA ⇒ aaA ⇒ aaa、…
    - 「a だけの列」または「b だけの列」で、長さ2以上のもの

### 2.2 有限オートマトン (Finite Automaton; FA)

- **正規文法と有限オートマトンは等価**
- 生成規則と状態遷移が1対1に対応する

#### 対応関係

| 生成規則 | オートマトンでの意味 |
|---|---|
| **A → aB** | 状態 A から a を読んで状態 B へ遷移 |
| **A → aA** | 状態 A から a を読んで A に戻る(**自己ループ**) |
| **A → a** | 状態 A から a を読んで**受理状態** へ遷移 |

- **start node**: 初期記号 S に対応する状態(矢印が外から入る)
- **halt node (受理状態)**: 二重丸で描く

#### 例(上の正規文法をFAに変換)

```text
S → aA | bB
A → aA | a
B → bB | b
```

- S --a--> A、S --b--> B
- A --a--> A(自己ループ)、A --a--> #(受理)
- B --b--> B(自己ループ)、B --b--> #(受理)
- **記号列の受理**: 開始状態から入力を1文字ずつ読んで遷移し、入力を読み切った時点で受理状態にいれば **受理 (accept)**、そうでなければ **棄却 (reject)**

### 2.3 NFA と DFA

- **非決定性FA (NFA)**: ある状態・ある入力記号に対して遷移先が**複数ありうる**(または遷移先がない)
- **決定性FA (DFA)**: ある状態・ある入力記号に対して遷移先が**ちょうど1つ**に定まる
- **定理**: 任意のNFAは、等価な(= 同じ言語を受理する)DFAに変換できる

#### 部分集合構成法

- **DFAの1状態 = NFAの状態の「部分集合」** とする
- 手順
    1. 初期状態は {S}
    2. 現在の状態集合 Q と入力記号 x に対し、Q の各状態から x で行ける先を全部集めた集合を新しい状態とする
    3. 行き先がない場合は **Φ(空集合、死状態)**。Φ からはどの入力でも Φ に留まる
    4. 新しい状態が出なくなるまで繰り返す
    5. **受理状態を1つでも含む部分集合**が、DFAの受理状態
- 講義スライドの例
    - {S} --a--> {A}、{S} --b--> {B}
    - {A} --a--> {A, #}(A の a は A へも # へも行けるため)、{A} --b--> Φ
    - {A,#} --a--> {A,#}、{A,#} --b--> Φ
    - {B} --b--> {B,#}、{B} --a--> Φ
    - {B,#} --b--> {B,#}、{B,#} --a--> Φ
    - 受理状態: **{A,#}, {B,#}**(# を含むから)
- 状態数は最悪 2ⁿ に増えうる(が、有限なのでDFAとして構成可能)

### 2.4 正規言語の反復補題 (Pumping Lemma)

#### 主張

- L を正規言語とする
- **L のみに依存する整数 p ≥ 1 が存在**し、
- 長さ **p 以上**の任意の文字列 `w ∈ L` は **w = xyz** と分解でき、次を満たす
    1. **|y| ≥ 1** (y は空でない)
    2. **|xy| ≤ p** (y は先頭 p 文字以内にある)
    3. **∀i ≥ 0 について xyⁱz ∈ L** (y を何回繰り返しても、削除しても L に属す)

#### なぜ成り立つか(直感 = 鳩の巣原理)

- L を受理するDFAの状態数を m とし、p = m とおく
- 長さ n ≥ p の文字列を受理するとき、通る状態列の長さは **n + 1** 個
- **n + 1 > m** なので、**鳩の巣原理**より**同じ状態が2回以上現れる**
- その重複した状態の間は**ループ**になっている
- ループ部分が y にあたる → 何周してもよいし、0周(スキップ)してもよい → xyⁱz ∈ L

```text
 q0 --a--> q1 --b--> q2 --c--> q1 --d--> q3(受理)
             └────── ループ ──────┘
    x = a,  y = bc,  z = d
    受理される: ad, abcd, abcbcd, abcbcbcd, …
```

#### 使い方: 正規でないことの証明

反復補題は「正規 ⇒ 性質P」なので、「性質Pが成り立たない ⇒ 正規でない」を示す。

### 2.5 L = {aⁿbⁿ : n ≥ 0} が正規言語でないことの証明

**背理法 + 反復補題**

1. **仮定**: L = {aⁿbⁿ} は正規言語であるとする
2. すると反復補題より、ある整数 **p ≥ 1** が存在する
3. **具体的な文字列を選ぶ**: **w = aᵖbᵖ** とおく。w ∈ L かつ |w| = 2p ≥ p なので補題が適用できる
4. 補題より **w = xyz** と分解でき、**|xy| ≤ p**, **|y| ≥ 1**
5. w の先頭 p 文字はすべて **a** であるから、|xy| ≤ p より **xy は a のみからなる** → **y = a^k (k ≥ 1)**
6. 補題の条件3で **i = 2** とすると $$xy^2z = a^{p+k}b^p \in L$$ でなければならない
7. しかし **p + k ≠ p** (k ≥ 1 なので) であり、a の個数と b の個数が一致しない → **aᵖ⁺ᵏbᵖ ∉ L**
8. **矛盾**。よって仮定は誤りで、**L は正規言語ではない** ∎

#### 直感的な理解

- `aⁿbⁿ` を認識するには「a を何個読んだか」を**数えて覚えておく**必要がある
- n は無限に大きくできるので、**有限個の状態では数え切れない**
- 「カウンタ(スタック)が必要」→ これは **文脈自由文法 / プッシュダウンオートマトン**の力が要る
- 実際、`S → aSb | ab`(または `S → aSb | ε`)という CFG で簡単に生成できる

## 3. 文脈自由文法とチョムスキー階層

### 3.1 文脈自由文法 (Context Free Grammar; CFG)

- 生成規則が **A → β** (A ∈ N, β ∈ (N ∪ T)*) の形
- 「左辺が**非終端記号ただ1つ**」がすべて。右辺は何でもよい
- 「文脈自由」= 周囲の文脈に関係なく、A はいつでも β に書き換えられる
- 例: `S → aSb | ab` → L = {aⁿbⁿ | n ≥ 1}

#### 例: 算術演算表現のための文法

**文法1(曖昧)**

```text
E → E+E | E-E | ExE | E/E | a | b | c | (E)
```

- `a + b × c` に対して**2つの異なる導出木**ができてしまう
    - (a + b) × c と解釈する木
    - a + (b × c) と解釈する木
- **演算子の優先順位・結合則が文法で表現できていない** → 曖昧 (ambiguous)

**文法2(非曖昧)**

```text
E → T | E+T | E-T      … 式 (Expression): +, - を扱う
T → F | TxF | T/F      … 項 (Term): ×, / を扱う
F → a | b | c | (E)    … 因子 (Factor): 最小単位
```

- **階層構造で優先順位を強制する**のがポイント
    - `×, /` は T の階層(下位)にあるので、必ず先にまとまる → **優先順位が高い**
    - `+, -` は E の階層(上位)なので、後からまとまる
- **左再帰** (`E → E+T`) により **左結合**も強制される
    - `a - b - c` → 必ず `(a - b) - c` の木になる(右結合の `a - (b - c)` はできない)
- 結果として、各文に対する導出木が**一意**になる

---

### 3.2 CFGの標準形

CFGは形が自由すぎて扱いにくいので、標準形に変換する。**どんなCFGも等価な標準形に変換可能**。

#### チョムスキー標準形 (Chomsky Normal Form; CNF)

- 規則の形は次の2種類のみ
    - **A → BC** (右辺は非終端記号ちょうど2個)
    - **A → a** (右辺は終端記号ちょうど1個)
- 導出木が**二分木**になる → **CKYアルゴリズム**が使える

#### グライバッハ標準形 (Greibach Normal Form; GNF)

- **A → aα** (a ∈ T, α ∈ N*)
- 右辺が必ず**終端記号1個で始まる**
- 導出のたびに終端記号が1つ確定する → 左から順に読む解析(トップダウン解析)に向く

---

### 3.3 練習: CNFへの変換

**元の文法**

```text
S → bA | aB
A → bAA | aS | a
B → aBB | bS | b
```

#### 手順

**Step 1: 終端記号を非終端記号に置き換える**(A → BC 内に終端が混ざってはいけない)

- `C_a → a`、`C_b → b` を新設する

**Step 2: 右辺の長さを2にする**(3個以上は新しい非終端記号で分割)

| 元の規則 | 変換 |
|---|---|
| S → bA | S → C_b A ✓(既に2個) |
| S → aB | S → C_a B ✓ |
| A → bAA | A → C_b A A(3個) → **A → C_b D₁, D₁ → A A** |
| A → aS | A → C_a S ✓ |
| A → a | ✓ そのまま(A → 終端1個 はCNF) |
| B → aBB | B → C_a B B(3個) → **B → C_a D₂, D₂ → B B** |
| B → bS | B → C_b S ✓ |
| B → b | ✓ そのまま |

#### 答え

```text
S  → C_b A | C_a B
A  → C_b D₁ | C_a S | a
D₁ → A A
B  → C_a D₂ | C_b S | b
D₂ → B B
C_a → a
C_b → b
```

- すべての規則が **A → BC** か **A → a** の形になっている ✓

### 3.4 チョムスキー階層 (Chomsky Hierarchy)

| 文法 | 言語 | 生成規則の形 | 受理するオートマトン |
|---|---|---|---|
| **0型** | 帰納的可算(制限なし) | α → β(制限なし) | **チューリング機械** |
| **1型** | 文脈依存 | α → β, **\|α\| ≤ \|β\|** | **線形拘束オートマトン** |
| **2型** | 文脈自由 | **A → β**, A ∈ N, β ∈ (N∪T)* | **プッシュダウンオートマトン** |
| **3型** | 正規 | **A → aB, A → a** | **有限オートマトン** |

- 包含関係(真部分集合): $$\text{正規} \subsetneq \text{文脈自由} \subsetneq \text{文脈依存} \subsetneq \text{制限なし}$$
- 上に行くほど**表現力が高い / 解析が難しい**、下に行くほど**制限が強い / 効率よく解析できる**
- `aⁿbⁿ` は文脈自由だが正規でない(§9で証明) → この包含が**真**であることの実例

#### 判定の手順(演習1で使う)

1. **左辺に非終端記号1個以外(2個以上の記号)が現れるか?**
    - Yes かつ **|左辺| ≤ |右辺| がすべて成立** → **1型(文脈依存)**
    - Yes かつ **|左辺| > |右辺| となる規則が1つでもある** → **0型(制限なし)**
2. 左辺がすべて非終端記号1個なら
    - すべての規則が `A → aB` / `A → a` の形 → **3型(正規)**
    - そうでない(右辺が自由) → **2型(文脈自由)**

- **原則: 最も強い(番号の大きい)クラスで答える。3型なら「2型でもある」が、答えは3型**

### 3.5 曖昧な文法 (Ambiguous Grammar)

- 1つの文に対して**複数の導出木**が存在する文法
- 例:

```text
S → SbS
S → ScS
S → a
```

- 文 `a b a c a` に対して
    - 木1: `S(a) b S(S(a) c S(a))` = `a b (a c a)`
    - 木2: `S(S(a) b S(a)) c S(a)` = `(a b a) c a`
- b と c の結合順序が文法で決まっていないため2通りできる
- **解消法**: 算術式の文法2のように、**階層(優先順位)を文法に埋め込む**

#### 自然言語における曖昧性

- "I saw a girl with a telescope" には**2つの解釈**がある
    - **VP付着**: 望遠鏡を使って(with a telescope が saw を修飾)少女を見た
    - **NP付着**: 望遠鏡を持った少女(with a telescope が a girl を修飾)を見た
- これは **PP付着曖昧性 (PP-attachment ambiguity)** とよばれる典型例
- 自然言語の曖昧性は文法だけでは解消できない → **確率・意味・文脈**が必要

## 4. 構文解析

### 4.1 単純な手法(トップダウン + バックトラック)

- 初期記号 S から導出を開始し、生成規則を決まった順序で適用していく
- 入力文が生成できなくなったら **バックトラック (backtracking)** して別の規則を試す

```text
S ⇒ NP VP ⇒ N VP ⇒ N V              ← "I saw" までしか作れず失敗 → 戻る
          ⇒ N V NP ⇒ N V N          ← 失敗 → 戻る
                   ⇒ N V DET N       ← "I saw a girl" まで OK、でも残りがある → 戻る
          ⇒ N V NP PP ⇒ N V N PP ...
```

- 問題: 試す組合せが指数的に増える → **組合せ爆発!**

### 4.2 CKY (Cocke-Kasami-Younger) アルゴリズム

**動的計画法**でこれを解決する。

- **特徴**
    - 入力から**ボトムアップ**に S を作りにいく
    - 解析の**中間状態を表(テーブル)のセルに保存**する(部分解の再利用 = DP)
    - **チョムスキー標準形 (A → BC)** の文法を用いる ← 二分割できることが本質
- **テーブルの意味**
    - `a(i, j)` = 入力の **i 番目から j 番目までの部分列**を導出できる非終端記号の集合
- **アルゴリズム**は次の通りである

```text
Input := w₁ w₂ … wₙ

# 対角要素(長さ1の部分列)を埋める
for i := 1 to n do
    a(i, i) = { A | A → wᵢ ∈ Lexical Rules }

# 部分列を短い方から長い方へ拡張
for d := 1 to n-1 do            # d = 幅 - 1
    for i := 1 to n-d do
        j = i + d
        for k := i to j-1 do    # 分割点 k
            a(i,j) = a(i,j) ∪ { A | A → BC ∈ P,
                                B ∈ a(i,k), C ∈ a(k+1,j) }

if (S ∈ a(1, n)) then accept else reject
```

- **要点**
    - 区間 [i, j] を **[i, k] と [k+1, j]** に分ける(分割点 k を全部試す)
    - 左半分が B、右半分が C を導けて、かつ `A → BC` があれば、A を a(i,j) に入れる
    - 最後に **S ∈ a(1, n)** なら受理
- **計算量**: **O(n³ · |G|)** — 指数時間だった素朴な手法が**多項式時間**になる
    - i の loop、d の loop、k の loop で n³
- **曖昧性の扱い**: 同じセルに同じ非終端記号が複数の導出経路から入りうる → **すべての解析結果を1つのテーブルにコンパクトに詰め込める**(パースフォレスト)

## 5. 依存構造解析

### 5.1 依存構造 (Dependency Structure)

- 句構造とは別の構文表現。**語と語を直接つなぐ**
- 用語は次のように対応する

| 用語 | 同じものを指す言い換え |
|---|---|
| **主辞 (head)** | governor, parent |
| **従属語 (dependent)** | modifier, child |

- 例: "I saw a big girl"
    - saw ← I(主語)、saw ← girl(目的語)、girl ← a、girl ← big
- 日本語: 「私は」「大きな→少女を」「見た」が主辞となる木
- 特徴
    - 語数 n に対してノード n(+ROOT)、辺 n 本 → **木構造**
    - 語順の自由な言語(日本語など)に向く

### 5.2 依存構造解析 = 最大全域木問題

- すべての語ペア (i, j) に**スコア s(i, j)**(i が主辞、j が従属語である尤もらしさ)を与える
- **完全有向グラフ**を作り、その中で**スコア総和が最大の全域木**を求める

$$\hat{y} = \arg\max_{y} \sum_{(i,j) \in y} s(i,j)$$

- ROOT から到達可能で、各語がちょうど1つの主辞を持つ有向木 = **有向最大全域木 (maximum spanning tree)**
- これを解くのが **Chu-Liu/Edmonds法**

---

### 5.3 Chu-Liu/Edmonds法

有向グラフの最大全域木を求めるアルゴリズム。

#### 手順

1. **貪欲法による選択**: 各ノード(ROOT以外)について、**入ってくる弧の中でスコア最大のもの**を1本ずつ選ぶ
2. **閉路がなければ終了** → それが最大全域木
3. **閉路があれば「閉路の縮約」**
    - 閉路 C を1つのノード **w_C** に縮約する
    - **C に入る弧のスコア**: 外部ノード x から C の頂点 v への弧について $$s(x \to w_C) = \max_{v \in C}\Bigl[, s(x \to v) + s(C) - s(a(v) \to v) ,\Bigr]$$
        - s(C) = 閉路内の弧のスコア合計
        - a(v) = 閉路内での v の親
        - 意味: 「x → v を採用すると、閉路内で v に入っていた弧 a(v)→v を**捨てる**ことになる」ので、その分を引く
    - **C から出る弧のスコア**: $s(w_C \to y) = \max_{v \in C} s(v \to y)$
    - どの v 経由で最大になったかを**記録しておく**
4. 縮約後のグラフで再帰的に 1. から繰り返す
5. **展開 (expand)**: 縮約を逆にたどり、記録した弧を復元して元のグラフ上の木に戻す

### 5.4 演習2: "John saw Mary yesterday" の依存構造

**スコア表** (行 X = 主辞, 列 Y = 従属語)

| X→Y | John | saw | Mary | yesterday |
|---|---|---|---|---|
| **ROOT** | -6 | -5 | -6 | -8 |
| **John** | — | 20 | 3 | 4 |
| **saw** | 30 | — | 30 | 15 |
| **Mary** | 4 | -7 | — | 8 |
| **yesterday** | 2 | -10 | 4 | — |

#### Step 1: 貪欲法による選択(各語の**入弧**で最大を選ぶ)

- **John への入弧**: ROOT(-6), saw(**30**), Mary(4), yesterday(2) → **saw → John (30)**
- **saw への入弧**: ROOT(-5), John(**20**), Mary(-7), yesterday(-10) → **John → saw (20)**
- **Mary への入弧**: ROOT(-6), John(3), saw(**30**), yesterday(4) → **saw → Mary (30)**
- **yesterday への入弧**: ROOT(-8), John(4), saw(**15**), Mary(8) → **saw → yesterday (15)**

#### Step 2: 閉路の検出

- **John → saw** と **saw → John** で **閉路 C = {John, saw}** が発生 ✗
- 閉路内スコア合計: **s(C) = 30 + 20 = 50**

#### Step 3: 閉路の縮約

**C に入る弧**

| 外部ノード x | 経由 v | 計算 | 値 |
|---|---|---|---|
| ROOT | John | -6 + 50 - 30 | 14 |
| ROOT | **saw** | **-5 + 50 - 20** | **25** ← 最大 |
| Mary | **John** | **4 + 50 - 30** | **24** ← 最大 |
| Mary | saw | -7 + 50 - 20 | 23 |
| yesterday | **John** | **2 + 50 - 30** | **22** ← 最大 |
| yesterday | saw | -10 + 50 - 20 | 20 |

- **ROOT → w_C = 25**(saw 経由と記録)
- **Mary → w_C = 24**(John 経由)
- **yesterday → w_C = 22**(John 経由)

**C から出る弧**

- **w_C → Mary** = max(John→Mary = 3, saw→Mary = 30) = **30**(saw 経由)
- **w_C → yesterday** = max(John→yesterday = 4, saw→yesterday = 15) = **15**(saw 経由)

**縮約後グラフ**(ノード: ROOT, w_C, Mary, yesterday)

|  | → w_C | → Mary | → yesterday |
|---|---|---|---|
| ROOT | **25** | -6 | -8 |
| w_C | — | **30** | **15** |
| Mary | 24 | — | 8 |
| yesterday | 22 | 4 | — |

#### Step 4: 縮約後グラフで再び貪欲法

- **w_C への入弧**: ROOT(**25**), Mary(24), yesterday(22) → **ROOT → w_C (25)**
- **Mary への入弧**: ROOT(-6), w_C(**30**), yesterday(8) → **w_C → Mary (30)**
- **yesterday への入弧**: ROOT(-8), w_C(**15**), Mary(8) → **w_C → yesterday (15)**
- **閉路なし** ✓ → 終了

#### Step 5: 展開

- **ROOT → w_C** は **saw 経由**で記録されていた → **ROOT → saw (-5)** を復元
- したがって閉路内では **saw に入っていた弧 John → saw (20) を削除**し、**saw → John (30) を残す**
- **w_C → Mary** は saw 経由 → **saw → Mary (30)**
- **w_C → yesterday** は saw 経由 → **saw → yesterday (15)**

#### 最終的な依存構造

```text
        ROOT
          │ -5
          ↓
        [saw]
       ╱  │  ╲
   30 ╱   │30 ╲ 15
     ↓    ↓    ↓
  John  Mary  yesterday
```

| 弧 | スコア |
|---|---|
| ROOT → saw | -5 |
| saw → John | 30 |
| saw → Mary | 30 |
| saw → yesterday | 15 |
| **合計** | **70** |

- **依存構造のスコア = 70**(Moodle にはこれを回答)
- 検算: 縮約グラフ上でも 25 + 30 + 15 = **70** で一致 ✓
- 言語的にも妥当: **saw が文の中心(述語)**で、John(主語)・Mary(目的語)・yesterday(時の副詞)がすべて saw に依存する
