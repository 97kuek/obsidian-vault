## ファイルシステムが解決する2つの問題

- ファイルシステムの仕事は、突き詰めると**2つの名前解決**である
  1. **ファイル名の変換**：人間が使う文字列の名前を、内部の ID に変換する（例：`/a/b/c` → `101020`）
  2. **ファイル内ポインタの変換**：ファイル内の「論理アドレス（先頭から何バイト目）」を、ストレージ上の「物理アドレス」に変換する
- ブロックデバイスは、固定長のセクタやブロックが番号順に並ぶ**線形なブロック空間**として捉えられる。通常ファイルのバイトオフセットを、ファイルシステムがこれらのブロックへ対応づける

### 論理アドレス→物理アドレスのマッピング

- ファイルの中身がディスク上のどこにあるかを管理する方式が3つある

#### 連続割り当て

- 各ファイルの「先頭アドレス」と「ファイルサイズ」を記録する
- シンプルだが、空き領域の断片化に弱い

#### リンク方式

- 「先頭アドレス」＋各ブロックに「次のブロックへのポインタ」を持たせ、数珠つなぎにする
- 途中のブロックへ飛びにくい

#### インデックス割り当て方式

- ファイルごとのインデックスブロックやi-nodeに、データブロックの位置を記録する

### UnixファイルシステムのAPI

- デバイスのときと同じ API が、ファイルにもそのまま使える

```c
fd = open(file, mode);
read/write(fd, buf, size);
lseek(fd, offset, mode);    // ファイルポインタの位置を移動
fstat(fd, statbuf);         // ファイルの情報を取得
close(fd);
```

- `lseek` は「ファイルポインタ（次に読み書きする位置）」を動かす命令である

## Unixファイルシステムの全体像

```
プロセスのデータ構造
   ↓
ファイルのデータ構造（オフセットを持つ）
   ↓
i-nodeテーブル ──→ i-node ──→ ファイルブロック（実データ）

ストレージ上には：
スーパブロック ／ i-nodeリスト ／ ファイルブロック
```

### i-nodeとは

- **i-node** は、ファイルシステム内のオブジェクトを管理するメタデータ
	- ファイルの中身そのものではなく、ファイルに関する情報を持っている
	- 所有者
	- アクセス権（誰が読み書きできるか）
	- アクセスタイム・変更時間
	- 実データの場所を示すブロック参照
	- ブロック参照の本数や、直接・間接参照の構成はファイルシステムの実装によって異なる
- i-node自身は通常ファイル名を持たない
- ディレクトリエントリが「名前 → i-node番号」を対応づけるため、複数の名前が同じi-nodeを参照できる

### ファイルデスクリプタとファイルデータ構造

![[Pasted image 20260719161428.png]]

- **プロセスがファイルを読み書きするまでのつながり**
- 不ァイルディスクリプタ→ファイルデータ構造→i-node→ファイルブロック（実データ）

> **ファイル名はi-nodeには入っておらず、ディレクトリがファイル名とi-nodeを結び付けている**

### スーパブロックとフリーブロック管理

- **スーパブロック**
	- そのファイルシステム全体の属性（ブロックサイズなど）を記録した、いわば「目次・台帳」
- **フリーブロック管理**
	- 空きブロックを**ビットマップ**（0/1 の並び）で管理し、「どこが空いていてどこが使用中か」を高速に判定する

### バッファキャッシュ

- ディスクアクセスはメモリに比べて圧倒的に遅いので、**一度読んだブロックはメモリ上にキャッシュとして残しておく**
- よく使うブロックは、2回目以降ディスクへアクセスせずに済む → 高速化
- キャッシュがいっぱいになったら、LRUやその近似などを用いて再利用可能性の低いページを回収する

### ディレクトリ管理

- ディレクトリの実体も、**名前と i-node 番号の対応表が書かれた特殊なファイル**
- 例えばルートディレクトリの中身は

```
名前        i-node番号
.       →   2     （自分自身）
..      →   2     （親、ルートなので自分）
usr     →   3
bin     →   10
```

- `/usr/local` をたどるときは、「ルートの i-node → usr（i-node 3）の中身を見る → local を探す…」と、**名前と i-node 番号を1段ずつたどっていく**ことでファイルにたどり着く

### ファイルシステムのマウント

- 複数のディスクを1つの木構造にまとめる仕組みが**マウント**である
- 実装としては、**マウントテーブル**で対応関係を管理する
- i-nodeへ単純なフラグを立てるかどうかなど、具体的な実装方法はOSやファイルシステムによって異なる
- これによりユーザーは複数のディスクを意識せず、ひとつながりのディレクトリツリーとして扱える

## ディスク

### ディスクの構造

1. 読みたいデータがある半径までヘッドを移動（シークタイム）
2. 円盤が回転して目的のセクタがヘッドの下に来るのを待つ（ローテーショナルレイテンシ）
3. セクタのデータを読み取る（転送時間）

![[Pasted image 20260719160529.png]]

### ディスクスケジューリング

- ディスクアクセス時のシークタイムのオーバーヘッドを削減したい
- アクセスするブロックの順番を変更することによりアームの動きを最小限にする
