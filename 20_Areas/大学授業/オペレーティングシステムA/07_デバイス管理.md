## オペレーティングシステムA：デバイス管理

- 親ノート: [[オペレーティングシステムA]]
- 担当: 中島（OS内部・仮想化）


## I/Oアーキテクチャ

![[Pasted image 20260719142328.png]]

- CPU・メモリ・グラフィックメモリが**バス**でつながり、その先に**バスコントローラ**を介してデバイスがぶら下がっている
- CPU とデバイスのやり取りには、2つの経路がある
	- **I/O ポート**（データのやり取り口）
	- **割り込み**（デバイス → CPU への「イベント発生したよ」という通知）

## デバイスドライバ

![[Pasted image 20260719142359.png]]

- ポイントは、**アプリ側は標準インタフェースで統一されていて、デバイス側だけがデバイス独自のプロトコル**になっていることである
- つまりデバイスドライバが「翻訳係」となり、デバイスごとの違いを吸収してくれる
- 新しいデバイスを使いたければ、対応するドライバを差し込めばよい、という設計である

## I/Oインタフェース

- Unix では、デバイスも**ファイルのように扱う**
- `/dev/device` のような名前でデバイスを表す
- 各デバイスは**メジャー番号**と**マイナー番号**を持つ
 - カーネル内部ではこの番号でドライバを識別する

## デバイスアクセスの方法

### (1) I/Oイベントの通知

- エラー通知・データ利用可能通知・状態通知などを受け取る方法として、**ポーリング**と**割り込み**の2種類がある

### (2) データの転送

- アプリケーションは `read` / `write` などのAPIで入出力を依頼する
- その裏側で、ドライバは主に次の転送方式を使う
- **プログラムI/O（PIO）**：CPUがデバイスレジスタとメモリの間でデータを転送する
- **DMA**：CPUが転送元・転送先・サイズなどを設定した後、DMAコントローラやデバイスがメモリとの転送を進める。CPUを完全に使わないわけではないが、大量データ転送中の負担を大きく減らせる

### デバイスのレジスタにアクセスする方法

- デバイスのレジスタにアクセスする方法も2通りある

|方式|しくみ|アクセス手段|
|---|---|---|
|**I/Oポート方式**|メモリ空間とは別に「I/O空間」があり、各デバイスにポートを割り当てる|専用命令（x86なら `in` / `out`）が必要|
|**Memory Mapped I/O**|デバイスの一部を「メモリの一部」として見せる|普通のメモリアクセス命令でOK（ただしアクセスコストは異なる）|

## ポーリング

- **ポーリング**は、「準備できた？まだ？」と**CPU が繰り返し確認し続ける**方式
- ビジーウェイトとして実装すると、**待っている間もCPUを使い続ける**のが欠点
- 一方、待ち時間が非常に短い場合やイベント頻度が極端に高い場合は、割り込み処理のオーバーヘッドを避けるためポーリングが有利なこともある

![[Pasted image 20260719155605.png]]

## 割り込み

- ポーリングの無駄を解決する

  1. デバイスドライバは I/O を設定したあと、`wait(&device)` で眠って、他の処理に譲る
  2. デバイスの処理が終わると、デバイスが CPU に**割り込み**をかける
  3. **割り込みハンドラ**が起動し、`wakeup(&device)` で眠っていた処理を起こす

![[Pasted image 20260719155710.png]]

- こうすれば、**待っている間CPUは他の仕事ができる**ため、長い待ち時間に対するビジーウェイトを避けられる
- ただし割り込みには、実行中処理の中断、ハンドラ実行、キャッシュへの影響などのコストがある
- 実システムでは、処理頻度や遅延要件に応じて割り込みとポーリングを使い分ける
