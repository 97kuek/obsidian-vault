## 情報通信ネットワークA：データリンク層

- 親ノート: [[情報通信ネットワークA]]

## データリンク層

### データリンク層とは

- TCP/IPモデルの中で**物理層とインターネット層の架け橋**になる層
- 物理層は「ビット（0と1）をケーブルや電波に流す」だけの世界で、ノイズによる誤りや、どこからどこまでが一つの意味あるデータかという区切りもない
- 一方インターネット層は「パケットを送りたい」と考えている
- データリンク層はこの間に立ち、同一リンク上のフレーム化、媒体アクセス、誤り検出などを担う
- 再送まで行うかはプロトコルによって異なり、常に無誤りの専用回線を提供するわけではない

#### 接続形態：LAN と WAN

- **LAN**
	- 同じ構内などの比較的狭い範囲のネットワーク
	- 古典的Ethernetや無線LANは媒体を共有するが、現在の有線Ethernetはスイッチによるポイントツーポイント接続が一般的である
- **WAN**
	- 離れた拠点やネットワークを結ぶ広域網
	- イントツーポイントだけでなく、事業者の共有網や仮想回線など多様な構成がある

#### データリンク層のプロトコルスタック

- **LANの場合、データリンク層は2層に分かれる**（論理リンク層＋MAC副層）
- WANはポイントツーポイントで多重アクセスがいらないのでMAC副層は不要
- **LANでは誰が回線を使うかを決める必要がある → だからMAC副層が追加される**

#### データリンク層が提供する主な機能

| 機能           | 処理層    | 内容                             |
| ------------ | ------ | ------------------------------ |
| サービスインターフェイス | 論理リンク層 | 上位層に対してサービス境界を提供               |
| フレーム化        | 論理リンク層 | ビットストリームをフレームに分割し、パケットとして上位へ渡す |
| 誤り制御         | 論理リンク層 | 物理層で生じた伝送誤りに対処し、上位層からできるだけ隠す   |
| フロー制御        | 論理リンク層 | 速い送信者が遅い受信者をデータであふれさせないよう流量を調整 |
| 多重アクセス       | MAC副層  | 共有媒体を複数端末が使うとき、送信機会を調整         |

#### NIC

- データリンク層の処理は、NICのハードウェア／ファームウェアとOSのデバイスドライバなどが分担して実装する
- PCとはPCI express、LANケーブルとはRJ45コネクタでつながる
- 最近のPCではNICは独立した周辺機器ではなく**マザーボードに内蔵**されているのが普通

#### 上位層に提供する3種類のサービス


| サービス               | 前提         | 例          | トランスポート層での類似物 |
| ------------------ | ---------- | ---------- | ------------- |
| **Ackなし・コネクションレス** | 個々のフレームに確認応答を返さない | 有線イーサネット   | UDPに近いが別層の概念 |
| **Ackあり・コネクションレス** | フレームごとに確認応答・再送を行う | 無線LANのユニキャスト | — |
| **Ackあり・コネクション指向** | 事前に論理リンクの状態を確立して信頼性を提供 | 一部のリンク制御プロトコル | TCPに近いが別層の概念 |

- 回線が綺麗なら確認応答すら省いて速く送る（イーサネット＝UDP的）
- 回線が悪いほど確認と接続管理で信頼性を担保する（衛星通信＝TCP的）

### フレーム化

#### なぜフレームに区切るのか

- **誤り制御がしやすい**
- **フロー制御がしやすい**
- **多重化しやすい**

#### 境目をどう決めるか

##### バイト数

- 先頭に「このフレームは何バイト」と書く
- その数のビットが化けると区切りがずれ、**それ以降が連鎖的にエラー**になる

##### バイト詰めを伴うフラグ・バイト

- 開始と終了を特別なパターンで示す
- データ中に同じ列が出たら直前に **ESC（例 `0x7D`）を挿入**
- ESC自身が現れたら**ESCの前にもう一つESC**を置く
- 受信側は「先頭のESCは常に削除」で復元

##### ビット詰めを伴うフラグ・パターン

- バイト詰めを**1ビット単位**で行う
- **連続6個の1でフレーム境界**を表し、送信側はペイロード中に**1が5個連続したら直後に0を挿入**
- 受信側は「1が5連続した直後の0」を取り除く

##### 物理層符号化違反

- 符号化の冗長性の未使用パターンに境界の意味を持たせる
- **詰め物によるオーバーヘッドがない**のが最大の利点

### 誤り制御

- **誤り検出**：誤りが起きたことだけ気づける冗長性をつけ、気づいたら**送信側に再送要求**
- **誤り訂正**：受信側が中身を復元できる十分な冗長情報をつけ、その場で直す（再送不要）

| 手法       | 適した状況                | 例                     |
| -------- | -------------------- | --------------------- |
| **誤り検出** | 誤り率が極めて低い回線          | 光ファイバー、品質の高い銅線        |
| **誤り訂正** | 誤り率が高い、または再送が原理的に不可能 | 無線リンク、CD/DVD/BD、QRコード |

- CDやQRコードは「もう一度送ってもらう」ができないので訂正符号が必須

#### パリティビット

- **1の個数が偶数（または奇数）になるよう**検査ビットを1ビット付ける
- 受信側は1の個数の偶奇を数えるだけ
- 弱点
	- **ランダムエラー**
	- **バーストエラー**は単一パリティでは検出できない
	- 対応策として、**インターリービング**があげられる
		- パリティを「転送順序とは違う順序（縦方向）」で計算し、バーストエラーを散らして孤立誤りとして検出できるようにする

#### チェックサム

- 一定幅の語へ分けて加算し、その補数などを検査値として付ける
- 具体的な加算方法と「正しいと判定する最終値」は、Internet checksumなど方式ごとに異なる

#### CRC

- パリティ・チェックサムより強力
- Ethernet, HDLC, Bluetooth, USB, gzip/png, MPEG-2 など適用例が広い
- ビット列を**係数が0/1の多項式**として扱い、演算はすべて**2の剰余系**
- 例 `110001` ↔ $x^5+x^4+1$


1. 元データの後ろに **r個の0** を付けて $S(x)=x^r D(x)$ を作る
2. $S(x)$ を $G(x)$ で割り算（mod 2、XORで引き算）する
3. 余り $R(x)$（rビット）がチェックサム
4. 送信データ $T(x)=S(x)-R(x)$ を送る
5. 受信側が $T(x)$ を $G(x)$ で割り、**余りが0なら誤りなし**

- 長さ $r$ 以下のすべてのバースト誤りを検出できる
-  $G(x)$ の選び方が重要（CRC-4: $x^4+x+1$、CRC-16/32 など）

### 誤り訂正

#### 反復符号

- 0→`000`、1→`111` と3回くり返し、受信側は**多数決**で復号
- **(3,1)符号**、符号化率 $1/3$
- 1ブロックで1ビットまで訂正できるが効率が悪い

#### 水平垂直パリティ検査符号 ((8,4)符号)

- データを2次元に並べ、縦と横の両方でパリティを計算。**誤った行と列の交点**として化けたビット位置を1点に絞り込める
- 例：1ビット化けると、その行と列のパリティだけが合わなくなり、交点が誤りビットと特定できる → 反転して訂正

#### 主要な誤り訂正符号

- **ハミング符号**：高速だが訂正能力は低い。メモリ・RAID2
- **畳み込み符号**：GSM・衛星・802.11、NASAボイジャー
- **リード・ソロモン符号**：訂正能力が高く**バーストエラーに強い**。CD/DVD/BD、DSL、衛星
- **LDPC**：理論限界（**シャノン限界**）に近い。10Gイーサ、802.11n/ac、WiMAX、4K/8K放送

### フロー制御

- 相手の状況に合わせて送信ペースを調整する
	- フィードバックなし（理想）
	- 逐次確認 
	- スライディングウィンドウ

#### 理想的なネットワーク

- 処理時間ゼロ・受信バッファ無限・通信路に誤りなし 
- → **フィードバック不要で最大転送率で送りっぱなし**

#### 逐次確認と ARQ

- **1フレーム送ったらACKが返るまで次を送らない**
- 誤りがあるとフレームやACKが失われるので **自動再送要求 ARQ**：ACKが来なければ**タイムアウト**で再送
- 「初回フレーム」と「再送された重複」を区別するためSeqを付ける

#### 東京―ワシントンD.C.間の最高伝送速度で計算してみる

##### 問題

> フレーム長を1,500バイト、伝播速度を光速、帯域を無制限、雑音なし、距離を約11,000 kmとする。東京―ワシントンD.C.間で逐次確認を行う場合の最高伝送速度を求めよ。

##### 解答

- 逐次確認では「1フレーム送る→ACK戻る」に**往復遅延(RTT)**だけかかり、その間1フレームしか送れない。上限＝1フレームのビット数 ÷ RTT
- RTT $= \dfrac{2 \times 11000\,\text{km}}{3.0\times10^8\,\text{m/s}} \approx 0.073$ 秒、1フレーム $1500\times8=12000$ ビット → $\dfrac{12000}{0.073} \approx \mathbf{163.6\ kbps}$
- 帯域無制限でも距離（遅延）が大きいと逐次確認は極端に非効率＝**long pipe problem**

#### RTTが大きい場合の高速化

##### 問題

> RTTが大きい場合、どのように伝送速度を向上させるか。

##### 解答

- ACKを待たずに複数フレームを先送りする、**スライディングウィンドウ**を用いる。

#### スライディングウィンドウプロトコル

- **ウィンドウサイズの範囲内ならACKを待たず複数フレームを同時送信**
- ACKが来るたびウィンドウを前へずらす

### メディアアクセス制御 (MAC)・多重アクセス

- 1本の共有チャネルを複数端末が使うとき「**次に誰が送信してよいか**」を決める制御＝**MAC**

| 区分                      | レイヤー    | 方式             | 特徴                    |
| ----------------------- | ------- | -------------- | --------------------- |
| **多重化（静的）** TDM/FDM/CDM | 物理層     | 時間・周波数・符号で固定分割 | 回線交換的<br>バースト性データに非効率 |
| **多重アクセス（動的）** CSMA等    | データリンク層 | フレーム単位で動的割当    | パケット交換的<br>バースト性に向く   |

#### ALOHA

- 1970年代初頭、ハワイ大学が離島とホノルルを短波無線でつなぐために開発
- **ピュアALOHA**：送りたいデータがあればいつでも送り、衝突したらランダム時間待って再送
- **スロット化ALOHA**：時間をスロットに区切り先頭でのみ送信

#### CSMA

- 送信前に**チャネルが使用中かを確認し、空いてから送る**
- **永続CSMA(1-persistent)**
	- 空いたら即送信
- **p-永続**
	- スロットごとに確率pで送信
- **非永続**：使用中ならランダム時間待ってから再確認
- 性能の優劣は負荷と遅延条件に依存する

- **CSMA/CD（衝突検出）**
	- 共有・半二重の古典的Ethernet
	- 送信中に衝突を検出すると送信を中止し、他端末も衝突を認識できるようジャム信号を送る
	- スイッチ式全二重Ethernetでは不要
- **CSMA/CA（衝突回避）**
	- 無線LAN(802.11)
	- 物理的に衝突検出できないので、空いた後**ランダムなバックオフ**を入れてから送信。衝突有無は**ARQ**で推定
- **指数バックオフ**
	- 衝突のたび待ち候補スロットを倍々に広げる
	- 混雑時に皆が散らばる
- CSMA/CAの分散制御モードを **DCF**（集中制御の PCF はほぼ使われない）

### データリンクプロトコルの具体例

#### IEEE 802 ファミリー

- IEEE 802委員会のLAN規格群
- **データリンク層だけでなく物理層も含めて標準化**
- 論理リンク制御(LLC)=802.2、有線=802.3、無線=802.11

#### イーサネット

- 1973-74年 Xerox PARC の**ロバート・メトカーフ**が開発
- **クラシック**：同軸ケーブル共有・半二重・CSMA/CD（指数バックオフ）
- **スイッチ式**：スイッチングハブで専用回路・原理的に衝突なし・全二重・CSMA/CD不要、100Mbps〜100Gbps超
- 規格表記 `N BASE-X`（N=速度、X=媒体: 2/5=同軸、T=ツイストペア、S/L=レーザー波長）
- **フレーム構造**：プリアンブル+SFD(8B)→宛先DA(6B)→送信元SA(6B)→Type/Length(2B)→データ＋Pad(46〜1500B)→**FCS（CRC-32で誤り検出）**
- **MACアドレス**：6バイト。前半3バイト=**OUI（組織識別子）**、後半3バイト=各組織がデバイスへ割当。スイッチは受信履歴から「どのポートにどのMAC」を**学習**
- **ループ対策**：ループは**ブロードキャストストーム**を起こすので、**スパニングツリー(STP/RSTP, 802.1D)**で木構造を作り余分なポートを閉じる

#### 無線 IEEE 802.11 / Wi-Fi

- **802.11(技術規格) と Wi-Fi(Wi-Fi Alliance の相互接続認定) は別物**
- 世代・地域・チャネル幅に応じて2.4GHz、5GHz、6GHz帯などを利用する
- MAC副層は基本的に半二重で、CSMA/CAとリンク層の確認応答を使う
- **動作モード**：AP経由の**インフラストラクチャモード**／端末直結の**アドホックモード**
- BSS（基本）→ESS（拡張、同じ**SSID**）
- **AP接続手順**：Probe→Beacon→Authentication→Association→Data
- フレームは データ/制御/管理 の3種

#### PPP (Point-to-Point Protocol)

- 1対1接続用
- 主にWAN（アナログ電話・ISDN・ADSL）
- イーサネットと違い**物理層の規定を含まない**
- コネクション型
