# 大規模言語モデル2026 第1回

- 親ノート: [[大規模言語モデル2026]]
- 派生ノート: [[大規模言語モデル2026_00_全体像]], [[日本のLLM開発環境]]

## 1. 言語モデルとは

- **定義**：単語列 $x_1, x_2, \dots, x_L$ に対して生成確率 $p(x_1, \dots, x_L)$ を割り当てる確率モデル

| 文 | 確率 |
|---|---|
| 日本の首都は東京 | 0.02 |
| 日本の首都はパリ | 0.00001 |
| 東京の首都は日本 | 0.0005 |

- 世界知識も文法も、すべて「確率」という一つの量に圧縮されている
- あらゆる言語タスクが「生成確率の推定問題」に還元できる

| タスク | 言い換え |
|---|---|
| QA | この質問に続くのにふさわしい答えは？ |
| 翻訳 | この英文に続くのにふさわしい日本語は？ |
| コード生成 | この指示文に続くのにふさわしいコードは？ |

- タスクごとに専用モデルは不要 → 「生成確率をどう求めるか」だけが技術的問題

## 2. 自己回帰言語モデル

- 課題：語彙 $V$ に対して $V^L$ 通りの同時分布を直接推定するのは不可能
- 解法：**確率の連鎖律**で分解

$$p(x_1, \dots, x_L) = p(x_1)\,p(x_2|x_1)\cdots p(x_L|x_1,\dots,x_{L-1})$$

- $L$ 個の「次単語予測」に分解される
- 副作用：確率推定器がそのまま生成器になる（→ LLMが「喋れる」理由）
- 注：LLaDA / MMaDA（**拡散言語モデル**）は自己回帰分解を捨てた別ルート。系列全体を並列にノイズ除去する

## 3. ニューラルLM → Transformer前夜

- 目的関数（負の対数尤度）：$\mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t})$

| モデル | 問題 |
|---|---|
| CNN / MLP | 受容野が有限。長いコンテキストを扱えない |
| RNN / LSTM | 逐次処理のため学習の並列化不可 → スケールできない。勾配消失 |

- 信号処理的に整理：CNN≒FIR（窓内しか見えない）、RNN≒IIR（無限の履歴を持つが時間再帰のため並列化不可）

## 4. Transformer（2017）

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

- 任意の2位置が1ステップで直接つながる（長距離依存が容易）
- 系列方向に再帰がない → 全時刻を行列積で一括計算 → GPU並列化可能

| モデル | BLEU | FLOPs |
|---|---|---|
| GNMT+RL | — | $2.3 \times 10^{19}$ |
| Transformer (base) | 27.3 | $3.3 \times 10^{18}$ |

- Transformerは「精度が高い」以上に**「計算効率が高い ＝ スケールさせる価値がある」**構造 → 後のスケーリング則につながる
- 当時はまだ翻訳（教師あり学習）での検証に限定

## 5. GPT（2018）

- Transformerを**事前学習**に転用
- 目的：次に来る単語を予測するだけ（教師データ不要、生テキストがあればいい）
- データ：BookCorpus（未公開書籍）
- 「教師なしで大量に学習できる目的関数」と「並列化してスケールできる構造」が初めて結合した

| モデル | パラメータ数 |
|---|---|
| GPT-1 | 117M |
| GPT-2 | 1.5B |
| GPT-3 | 175B |

- 構造はほぼ同じままデータ量とパラメータ数だけを増やす路線

## 6. なぜ今LLMか ：スケールと汎用性

### Scaling Law（Kaplan+ 2020）

- テストロスが3変数（計算資源 $C$、データ量 $D$、パラメータ数 $N$）のべき乗則に従う

$$L = (C_{\min} / 2.3 \times 10^8)^{-0.050}$$

- log-logプロットで直線 = 「いくら計算資源を積めばどれだけ性能が上がるか」が事前に予測可能 → 研究が投資判断の対象に

### Emergent Ability（Wei+ 2022）

- 個別タスクの精度はなめらかに上がらない
- $10^{22}$〜$10^{24}$ FLOPs 付近の閾値を超えるとランダム同然の精度が突然立ち上がる
  - 例：modular arithmetic、word unscramble、multi-task NLU
- モデルが巨大なときだけ解けるタスクが存在する → 小さいモデルで実験して外挿するだけでは何ができるようになるか分からない

### Few-shot / Zero-shot（GPT-3, Brown+ 2020）

```
Few-shot:  Translate English to French:
           sea otter => loutre de mer
           peppermint => menthe poivrée
           cheese =>

Zero-shot: Translate English to French:
           cheese =>
```

- モデルの重みを1つも更新せず、入力の書き方だけで挙動が変わる → これが「汎用性」の正体

## 各回ダイジェスト

### 第2回：推論（Prompting / In-context Learning）

**Few-shot / Zero-shot（GPT-3論文, Brown et al. 2020）**
- Few-shot：タスク説明＋いくつかの例をプロンプトに入れる
- Zero-shot：タスク説明だけ
- いずれもパラメータを更新しない → **In-context Learning**

**Chain-of-Thought（CoT）（Wei et al. 2022）**
- 多段階推論タスクで答えだけでなく「途中の思考過程」を例示
- 例：標準プロンプト→27（誤答）、CoT→「23−20=3、3+6=9」→9（正答）

**Zero-shot CoT（Kojima et al. 2022）**
- `A: Let's think step by step.` という一文を差し込むだけ
- 玉突き問題の正答が8→4（正解）に変化
- 推論能力はモデル内部に既にあり、引き出し方の問題だったことを示す

**Self-Consistency（Wang et al. 2023）**
- Top-k / Top-p サンプリングで複数の推論経路を生成し、最終answerの**多数決**を取る
- 直感：正解への道は複数あるが、誤答の仕方はバラバラ
- テスト時計算量を増やして精度を買う手法 → 後の「推論のスケール則」の原型

**GEPA（Agrawal et al. 2025）**
- プロンプトの自動最適化
- 成功・失敗の軌跡を**言語フィードバック**としてプロンプトを書き換え（数値報酬ではなく自然言語で反省）
- 候補選択でパレート的多様性を確保（「1問だけでも最高スコアを出したプロンプト」も残す）
- HotpotQA / Qwen3-8B でMIPROv2・GRPOを上回り、ロールアウト数は桁違いに少ない

### 第3回：事前学習

**Transformer構成要素**
- Embedding / Multi-Head Attention / Feed Forward
- その他：LayerNorm, Positional Encoding, 残差接続

**アテンション機構**
- 全トークン間の類似度（ベクトルの内積）で長距離依存を捉え、必要な情報を柔軟に取捨選択する
- RNNと違い並列計算可能（スケールを可能にした要因）

Query・Key・Valueの流れ：
1. 各入力から q, k, v を生成
2. queryと各keyの内積でscoreを計算
3. scoreでvalueを重み付き和してoutputを得る

**アテンションの可視化例**
- "The animal didn't cross the street because it was too tired." の "it" が "The animal" に強くアテンション
- 共参照解析を教えていないのに、次単語予測の副産物として獲得される → 事前学習の本質
- 注：実際のアテンションヘッドはここまで解釈しやすくない

**3つのアーキテクチャ**

| 型 | 例 | 用途 |
|---|---|---|
| Encoder-only | BERT, RoBERTa | 認識系（分類） |
| Encoder-Decoder | BART, T5 | テキスト生成 |
| **Decoder-only** | GPT, Llama, Qwen, DeepSeek | テキスト生成（現在の主流） |

**事前学習の実体**
- Webから集めた文章でひたすら次単語予測をするだけ
- 「春 → は」「春は → 桜」…と予測し、正解との交差エントロピーを最小化
- この単純なタスクの反復から「春・桜・綺麗が強く結びつく」といった世界知識が立ち上がる

### 第4回：スケール則

$$L = (N/8.8\times10^{13})^{-0.076},\quad L = (D/5.4\times10^{13})^{-0.095},\quad L = (C_{min}/2.3\times10^{8})^{-0.050}$$

- 計算資源 $C$・データ量 $D$・パラメータ数 $N$ の増加でテスト損失がべき乗則で低下
- 両対数軸で直線 → 資源を投入するほど性能が上がることが**予測可能な形**で分かった
- OpenAIがこれに賭けて大規模開発に踏み切り、投資合戦が始まった
- 画像生成・マルチモーダル・動画・数理でも同様のスケール則が成立（モダリティを問わない普遍性）

**三種の神器**（スケール則から演繹される帰結）

| 要素 | 意味 |
|---|---|
| ① 大規模計算資源 | ハードウェア投資 |
| ② 大規模データ | 法整備（著作権・個人情報） |
| ③ 優秀な人材 | 人的資本投資（試行錯誤の担い手） |

**スケール則の拡張**
- 事後学習のスケール則
- **推論（test-time compute）のスケール則**（Snell et al., 2024）
- 現状：フロンティアは事前学習から事後学習・推論に移っている。高品質データ合成とRLによるreasoning学習が急拡大、RLスケールの方法論はまだ成熟していない

### 第5回：事前学習（上級編）

**Sparse Transformer**
- Attentionの計算箇所を限定して $O(n^2)$ を削減（strided / fixed の2パターン）
- 2回通せば全トークンに到達（1回のstrided attentionでは届かないトークンがある）
- 画像・音声など長系列モダリティへの応用を可能にする

**Switch Transformer（MoE）**
- 1.6兆パラメータのMoE
- FFNを複数エキスパートに分け、Routerがトークンごとに1つ選ぶ
- 総パラメータは巨大だが、1トークンあたりの実効計算量は小さい（Nを増やしつつCを抑える）
- DeepSeek-V3などの現在のモデルに受け継がれている

**LLM.int8()（量子化）**
1. 隠れ状態から列単位で外れ値（閾値超え）を抽出
2. 外れ値の列はFP16のまま、それ以外はINT8に量子化して行列演算
3. INT8出力をFP16に戻して加算
- **ポイント**：外れ値の列だけが性能に致命的に効く

**大規模分散学習**

| 並列化 | 方法 | 特徴 |
|---|---|---|
| データ並列 | モデル全体を各GPUに複製 | 効率出しやすいが極端に大きなモデルは載らない |
| パイプライン並列 | レイヤごとに分割 | モデル並列の一種 |
| テンソル並列 | 層内の巨大行列を分割 | 実装が重く、効率を出せるモデルが限られる |

- 実務では3つを組み合わせる（3D parallelism）

### 第6回：ファインチューニング

**SFT（教師ありファインチューニング）**
- QAデータ・チャットデータで学習
- 学習手法は事前学習と同じ次単語予測
- 違いは「**Aの部分にだけ損失をかける**」点
- 「新しい学習パラダイム」ではなく「データの中身とマスクが違うだけ」

**Instruction Tuning（FLAN, Chung et al.）**
- 1.8Kタスクで多タスク学習 → 未知タスクにもzero-shotで従えるようになる
- CoT付きデータを混ぜると推論能力も汎化

**LoRA（Hu et al. 2021）**
- 事前学習重み $W$ を凍結し、低ランク行列 $BA$（$B$: 0初期化、$A$: ガウス初期化、ランク $r \ll d$）だけを学習 → $W + BA$ として使用
- 仮説：微調整で必要な重み更新は本質的に低ランク
- WikiSQL：Fine-Tuneが $10^{11}$ 相当の学習パラメータで達成する精度を、LoRAは $10^{7}$ 程度で並ぶ

### 第7回：強化学習

**RLHF**
- 人間の価値観（有害なことを言わない等）に沿うようLLM出力を調整
- 3つの応答を〇△✕でランク付け → 報酬シグナルに使用
- 教師あり学習に比べて情報量が圧倒的に少ない（正解文ではなく良し悪しのスカラーのみ）

**DPO（Rafailov et al.）**
- 報酬モデルを明示的に構築せず、選好データから**直接分類問題として**方策を最適化
- 言語モデル自身が暗黙の報酬モデルである → 最適方策が閉形式で書ける
- RLループが不要 → 実装が劇的に簡単に

**GRPO（DeepSeek）**
- PPOからValue Modelを削除
- 同じ質問に対して $o_1 \dots o_G$ をグループでサンプル
- 報酬 $r_1 \dots r_G$ のグループ内統計（平均・標準偏差）からアドバンテージを推定
- Value Modelが不要になり、学習コストを大幅削減

**"Aha Moment"（DeepSeek-R1）**
- RLの結果、教えていないのにモデルが `Wait, wait. Wait. That's an aha moment I can flag here.` と自己修正を創発
- 訓練が進むにつれ：AIME精度が単調に上昇、1応答あたりの平均トークン長も単調に上昇
- 「長く考えるほど良い答えに辿り着く」という戦略をRLが自発的に発見 → reasoning modelの根拠

**SLM（Small Language Model）への潮流**
- 背景①：小さいモデルでも、より多くのデータで長く学習すれば高性能に到達できる
- 背景②：推論コスト（運用コスト）まで含めると小さいモデルの費用対効果が高い

**Chinchilla Trap（"Go smol or go home"）**
- Chinchilla則は「訓練計算量が最小になるNとDの比」を与えるが、推論コストを一切考慮していない
- 最適モデルサイズの40〜60%のサイズを選び、訓練計算量を10〜42%追加すれば同性能に到達
- 訓練は一度、推論は無限回 → 小さいモデルを長く学習させる方が得

### モデルの大規模化の潮流

- 2018 GPT-1 (117M) → 2019 GPT-2 (1.5B) → 2020 GPT-3 (175B) → 2023 GPT-4（非公開）
- 構造は2017年のTransformerのまま、スケールだけ変えた
- GPT-4以降、フロンティアモデルはパラメータ数を非公開

**「知識量からパラメータ数を逆算」する推定手法（_Incompressible Knowledge Probes_）**
1. パラメータ数既知のオープンモデル（89個）で事実知識クイズ（IKP Score）を測定
2. `正答率 ∝ log₁₀(パラメータ数)` で回帰（R² = 0.917）
3. クローズドモデルの正答率を測り、回帰直線に外挿

| モデル | 点推定 | 90%予測区間 |
|---|---|---|
| GPT-5.5 | 〜9.7T | 3.2T – 28.7T |
| Claude Opus 4.6 | 〜5.3T | 1.8T – 15.6T |

- 区間が上下1桁ずつ開いている → 「9.7T」は「3兆かもしれないし29兆かもしれない」という意味
- 落とし穴①：MoEの場合、推論コストに効くのは活性パラメータ（総パラメータとは別物）
- 落とし穴②：正答率は学習データ質・量、事後学習、思考モードにも強く依存する
- 数字そのものより「そう推定するしかないほどブラックボックス化した」という事実のほうが情報量が大きい

### モデル構造の動向

**収束しつつある7つの設計**

| 設計 | 理由 |
|---|---|
| **pre-norm** | LayerNorm を残差ブロックの前に置く。勾配が深いモデルでも安定する（post-normはwarmup必須で壊れやすい） |
| **RMSNorm** | $\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum x_i^2}} \cdot g$。平均計算を省いて速い |
| **bias 項の全削除** | 効果がほぼゼロ。学習を不安定にすることがあり、パラメータも減る |
| **SwiGLU / GeGLU** | $\text{SwiGLU}(x) = (\text{Swish}(xW_1) \odot xW_2)W_3$。隠れ次元を2/3に調整。素のReLU FFNより一貫して強い |
| **RoPE** | 位置を回転行列としてQ・Kに掛ける。内積が相対位置 $(m-n)$ だけの関数 → 学習長を超えた外挿もしやすい |
| **GQA** | 複数のQuery headでK,Vを共有。KVキャッシュを1/8などに削減 → メモリ帯域律速な推論の高速化 |
| **局所+グローバルattentionの交互配置** | 多くの層はスライディングウィンドウで十分。数層に1回だけ全体を見る → 長文コンテキストのコストを大幅削減 |

- これらはすべて「性能を落とさずに速く・安定させる」工学的最適化 → **アーキテクチャの探索はほぼ終わり、勝負はデータと事後学習に移った**

**ハイブリッドアーキテクチャ（Qwen3.5、Nemotron 3）**

| 機構 | 計算量 | 状態サイズ | 特徴 |
|---|---|---|---|
| Attention | $O(L^2)$ | $O(L)$（KVキャッシュ） | 全過去を厳密に参照できる |
| SSM / 畳み込み系 | $O(L)$ | 固定 | 過去を圧縮して持つ。特定固有名詞のコピーが苦手 |

- 1:7くらいの比率でattention層を混ぜる → 精度を保ちつつ長文推論のメモリと速度が改善

**Claude Mythos 構造の仮説（第三者による外部推測）**

```
[通常]  X → Layer1 → Layer2 → Layer3 → Layer4 → Y   (4層ぶんの重み)
[再帰]  X → Layer1 ↺ ↺ → Layer3 ↺ ↺ → Y            (2層ぶんの重み、計算は同じ)
```

- 同じ層を複数回通す（recurrent depth / layer looping）
- 重みは共有 → パラメータは半分。推論時にループ回数を増やせば「重みを増やさずに考える深さだけ増やせる」
- 770M パラメータが 1.3B の Transformer に匹敵という報告あり
- **注：Anthropicの公式発表ではなく第三者の推測。`kyegomez/OpenMythos` は公式性・検証の質が玉石混交**
- 学ぶべき点：「再帰的深さ」という設計軸が推論能力を伸ばす有力候補として真剣に議論されていること

### 学習方法の進展

**SGS（Scaling Self-Play with Self-Guidance、Agrawal et al. 2025）**

- 問題意識：RLには「解けそうで解けない」問題が大量に要る。人間作成のデータセットは有限
- 解法：LLMに3役を担わせる自己対戦

| 役割 | 機能 |
|---|---|
| Proposer（出題者） | 新しい定理・命題を生成 |
| Guide（審査者） | ①ちょうどいい難易度か ②元の未解決問題と関連があるか を評価 |
| Solver（解答者） | 生成された問題をRLで解き、その経験で強くなる |

- Guide Scoreの高い「難しすぎず・関連がある」問題を選んでカリキュラムを自動生成 → 能力の境界が外側に広がる

| 手法 | 最終精度 |
|---|---|
| RL Baseline | 60.3%で漸近 |
| SGS | 67.1%、漸近が遅い |

- **「頭打ちの高さが変わっている」**：問題生成側にも学習を回すことでスケーリングの天井を上げられる
- IMO・ICPCの結果は「検証可能な報酬 × 自己生成カリキュラム」の系譜

- 「日本のモデルは小さい」と単純に比較できない
