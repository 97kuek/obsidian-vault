## 1. 言語モデルとは

- **定義**：単語列 $x_1, x_2, \dots, x_L$ に対して生成確率 $p(x_1, \dots, x_L)$ を割り当てる確率モデル

| 文 | 確率 |
|---|---|
| 日本の首都は東京 | 0.02 |
| 日本の首都はパリ | 0.00001 |
| 東京の首都は日本 | 0.0005 |

- 世界知識も文法も、すべて「確率」という一つの量に圧縮されている
- あらゆる言語タスクが「生成確率の推定問題」に還元できる

| タスク | 言い換え |
|---|---|
| QA | この質問に続くのにふさわしい答えは？ |
| 翻訳 | この英文に続くのにふさわしい日本語は？ |
| コード生成 | この指示文に続くのにふさわしいコードは？ |

- タスクごとに専用モデルは不要 → 「生成確率をどう求めるか」だけが技術的問題

## 2. 自己回帰言語モデル

- 課題：語彙 $V$ に対して $V^L$ 通りの同時分布を直接推定するのは不可能
- 解法：**確率の連鎖律**で分解

$$p(x_1, \dots, x_L) = p(x_1)\,p(x_2|x_1)\cdots p(x_L|x_1,\dots,x_{L-1})$$

- $L$ 個の「次単語予測」に分解される
- 副作用：確率推定器がそのまま生成器になる（→ LLMが「喋れる」理由）
- 注：LLaDA / MMaDA（**拡散言語モデル**）は自己回帰分解を捨てた別ルート。系列全体を並列にノイズ除去する

## 3. ニューラルLM → Transformer前夜

- 目的関数（負の対数尤度）：$\mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t})$

| モデル | 問題 |
|---|---|
| CNN / MLP | 受容野が有限。長いコンテキストを扱えない |
| RNN / LSTM | 逐次処理のため学習の並列化不可 → スケールできない。勾配消失 |

- 信号処理的に整理：CNN≒FIR（窓内しか見えない）、RNN≒IIR（無限の履歴を持つが時間再帰のため並列化不可）

## 4. Transformer（2017）

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

- 任意の2位置が1ステップで直接つながる（長距離依存が容易）
- 系列方向に再帰がない → 全時刻を行列積で一括計算 → GPU並列化可能

| モデル | BLEU | FLOPs |
|---|---|---|
| GNMT+RL | — | $2.3 \times 10^{19}$ |
| Transformer (base) | 27.3 | $3.3 \times 10^{18}$ |

- Transformerは「精度が高い」以上に**「計算効率が高い ＝ スケールさせる価値がある」**構造 → 後のスケーリング則につながる
- 当時はまだ翻訳（教師あり学習）での検証に限定

## 5. GPT（2018）

- Transformerを**事前学習**に転用
- 目的：次に来る単語を予測するだけ（教師データ不要、生テキストがあればいい）
- データ：BookCorpus（未公開書籍）
- 「教師なしで大量に学習できる目的関数」と「並列化してスケールできる構造」が初めて結合した

| モデル | パラメータ数 |
|---|---|
| GPT-1 | 117M |
| GPT-2 | 1.5B |
| GPT-3 | 175B |

- 構造はほぼ同じままデータ量とパラメータ数だけを増やす路線

## 6. なぜ今LLMか ：スケールと汎用性

### Scaling Law（Kaplan+ 2020）

- テストロスが3変数（計算資源 $C$、データ量 $D$、パラメータ数 $N$）のべき乗則に従う

$$L = (C_{\min} / 2.3 \times 10^8)^{-0.050}$$

- log-logプロットで直線 = 「いくら計算資源を積めばどれだけ性能が上がるか」が事前に予測可能 → 研究が投資判断の対象に

### Emergent Ability（Wei+ 2022）

- 個別タスクの精度はなめらかに上がらない
- $10^{22}$〜$10^{24}$ FLOPs 付近の閾値を超えるとランダム同然の精度が突然立ち上がる
  - 例：modular arithmetic、word unscramble、multi-task NLU
- モデルが巨大なときだけ解けるタスクが存在する → 小さいモデルで実験して外挿するだけでは何ができるようになるか分からない

### Few-shot / Zero-shot（GPT-3, Brown+ 2020）

```
Few-shot:  Translate English to French:
           sea otter => loutre de mer
           peppermint => menthe poivrée
           cheese =>

Zero-shot: Translate English to French:
           cheese =>
```

- モデルの重みを1つも更新せず、入力の書き方だけで挙動が変わる → これが「汎用性」の正体

### 基盤モデル（Foundation Model）

- Stanford CRFM（2021）が導入した語
- 定義：「広範なデータで大規模に訓練され、多様な下流タスクに適応可能なモデル」
- "critically central yet incomplete"（決定的に中心的だが未完成）という慎重な語感を持つ名称

## 7. なぜ今LLMか ：言語以外への波及

- **マルチモーダル化**：GPT-4Vは画像を入力に取り自然言語で回答

### ロボティクスへの展開

1. **Say-Can (2022)** — LLMのスコア（言語的な尤もらしさ）× Value Function（実行可能性、TD学習）で行動選択。実行可能な低レベルスキルはあらかじめ用意されている
2. **RT-1 (2022)** — EfficientNet + Transformer。EDR 13台 × 17ヶ月 × 744タスク × 13万デモ。訓練タスクで97%成功。「言語モデルのレシピを行動データにそのまま適用」
3. **RT-X / Open X-Embodiment (2023, ICRA 2024 Best Paper)** — Google DeepMind + 21機関。22種ロボット、527スキル、100万エピソードを統一フォーマットで集約
4. **π₀ (2024)** — VLA（Vision-Language-Action）モデル。洗濯物を畳む、卵を割らずにケースに入れる

### World Simulator（Sora）

- OpenAIは動画生成モデルを "world simulators" と位置づけ
- テキストから物理的に整合した映像を生成できる = 世界のダイナミクスを内部に持っている可能性を示唆

### AIRoA

- アカデミア主導・オープン・報酬設計を特徴とする日本発の取り組み

## 8. Context Engineering

| 層 | 構成要素 |
|---|---|
| Context Retrieval & Generation | Prompt Engineering、External Knowledge Retrieval（RAG）、Dynamic Context Assembly |
| Context Processing | Long Sequence Processing、Self-Refinement、構造化情報の統合 |
| Context Management | 基本制約、Memory階層とストレージ、Context Compression |

- Prompt Engineering が「プロンプトの文言をいじる」に矮小化されたのに対し、Context Engineering は「**コンテキストウィンドウに何をどう詰めるか**」という設計問題全体を指す
- RAG・ツール利用・Deep Research・Memoryがすべてこの傘の下に入る

## 9. 評価の高度化

| ベンチマーク | 概要 |
|---|---|
| **SWE-Bench** | GitHub Issueを与えてPRを生成させる。評価はユニットテストが通るか（実際の開発ワークフローそのもの） |
| **Humanity's Last Exam (HLE)** | 極端に難しい専門問題。登場時点でSoTA 9% → 現在21.6% |

- MMLU / MATH / GPQAはどのモデルも高得点（飽和）→ HLEだけが軒並み一桁
